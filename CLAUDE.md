# CLAUDE.md

Claude Code plugin marketplace for **Maister** — structured, standards-aware SDLC workflows. Plugin source is `plugins/maister/`; `make build` builds the GitHub Copilot CLI variant from it into the ignored `dist/copilot/`, and CI publishes that build to the `dist/beta` and `dist/stable` branches.

This file guides work **on this repository**. Plugin consumers never see it — runtime behavior (phases, gates, delegation, artifact contracts) must live in `SKILL.md`, agent, and reference files under `plugins/maister/`, never here.

## Layout

```
.claude-plugin/marketplace.json   # Claude Code marketplace: name, version, maister → ./plugins/maister
.github/plugin/marketplace.json   # Copilot CLI marketplace: name, version, maister → dist/<channel>:copilot/
.claude/rules/                    # Path-scoped authoring rules (auto-load when editing plugin source)
plugins/maister/                  # Plugin source — edit here
  .claude-plugin/plugin.json      #   Plugin manifest
  lib/*.mjs                       #   Executable code shared by more than one skill
  skills/<name>/SKILL.md          #   Skills (+ optional references/, assets/, server/)
  agents/*.md                     #   Subagents
  commands/*.md                   #   Slash commands (thin wrappers; flat, no subdirs)
  hooks/hooks.json                #   Lifecycle hooks; Node `*.mjs` hooks alongside; `modules` names display.mjs
  types/index.d.ts                #   State contract of the Claude Code hooks module (display.mjs)
  interface.json                  #   GENERATED by `make build`: the plugin's public interface, for consumers to diff
dist/copilot/                     # Copilot CLI build (make build, make validate); ignored, never committed
platforms/copilot-cli/build.sh    # The generator
tools/interface.mjs               # Generates each tree's interface.json (dev tooling, never shipped)
tools/publish-dist.sh             # CI's publish of the Copilot build to dist/<channel> (dev tooling, never shipped)
tests/                            # Engine verb suite (`make test`) + committed fixtures — never under plugins/
docs/                             # User-facing docs (workflows.md, commands.md)
README.md                         # User-facing install/usage
CONTRIBUTING.md                   # Contributor loop (make targets); license inbound=outbound
```

## Hard rules

- **Never commit a Copilot build.** `dist/copilot/` is generated from `plugins/maister/` by `make build` and ignored by git. CI builds it on each push to `beta` and `master` and commits it to `dist/beta` or `dist/stable`, folder `copilot/`: one commit per changed build, naming its source commit. Only CI writes those branches, and nothing force-pushes them. Commit the source only, with `plugins/maister/interface.json` when `make build` changed it.
- **`SKILL.md` is uppercase.** Skills live at `skills/<name>/SKILL.md`.
- **The compatibility contracts register is a Pro Edition feature** and does not live in this repository.
- **The compatibility floor is plugin 2.2.3.** The frozen shapes describe task directories written by 2.2.3 or newer; older ones are listed by name/date/type only — never parsed, rendered or resumed. No migration path exists, and none is to be added.
- **Inventories are not kept here.** Skills, agents, and commands are self-describing via frontmatter — `ls` the directories instead of expecting a catalog in this file.

plugin source, the guide template lint (`tests/guide-template-lint.mjs`: every workflow guide follows the step template), the frontmatter lint (`tests/frontmatter-lint.mjs`: every skill, agent and command frontmatter is valid YAML), the gate-title lint (`tests/gate-title-lint.mjs`: no two gates of one workflow ask the same question), the browser-tool lint (`tests/browser-tool-lint.mjs`: neither plugin tree ships an MCP server, names one browser tool's output folder or plugin-scoped tool names, or grants a browser server in a Copilot allowlist), the dispatch-command lint (`tests/dispatch-command-lint.mjs`: every code span that invokes `dispatch-model` with a flag names it as `workflow.mjs dispatch-model`, in either plugin tree), the plugin-path lint (`tests/plugin-path-lint.mjs`: no agent and no workflow guide names a plugin file by a bare relative path — a code span opening with `skills/<skill>/…` or `<skill>/references|scripts|assets|server/…` or `<skill>/SKILL.md` must open with `<plugin root>/` instead), the containment lint (every source agent, and its generated copy, carries the containment sentence), the scratch-file lint (every agent, and its generated copy, carries the scratch-file sentence: throwaway files in a `mktemp -d` directory or under `${TMPDIR:-/tmp}`, never a literal `/tmp`), the search-scope lint (every agent, and its generated copy, carries the search-scope sentence: no search outside the project and the paths its prompt names), the prose-colon check (no `maister:` before a space or a line end in the source markdown, which the Copilot build would strip to a dangling word), the marketplace lint (`tests/marketplace-lint.mjs`: both marketplace files and the source `plugin.json` agree on name and version, and each lists only its own host's `maister`), the gate-rule lint (exactly 8 files carry the gate-rule sentence and 10 its tail) and the hook-runtime check (no hook needs bash or jq: no `*.sh` hook, | `make test` | Build the variant into a scratch folder, then run the engine verb suite (`node --test`, Node ≥ 20, no dependencies) over the committed fixtures in `tests/` |
| `make smoke` | Run the engine verbs through bash and the hooks as `hooks.json` starts them, from paths holding a space (`tests/shell-smoke.mjs`; CI also runs it under pwsh, Windows PowerShell, cmd.exe and Git Bash on Windows) |
| `make test-mod` | `claude plugin validate` the plugin, then run the hooks module's tests (`tests/mod/`) with `claude plugin test` on a scratch copy; skipped without the `claude` CLI |

| `make watch` | Rebuild on change (requires `fswatch`) |

`make validate` also checks that every command `hooks.json` names exists on disk and that
`plugins/maister/interface.json` matches a fresh generation from its code; CI also fails when
`make build` leaves the tree changed. The interface file's gate-request and checkpoint keys come from
`skills/workflow-engine/scripts/lib/interface-shapes.mjs`, which the request builders use too; a
key added to a request is declared there, or `tests/engine/interface-file.test.mjs` fails. `make test` covers the engine's verbs
behaviourally: the freeze, state writes and refusals, the dashboard projection, gates, sub-runs,
`run-complete` and `sync-plan`, each run as a subprocess against a scratch copy of
`tests/fixtures/`. A change under
`skills/workflow-engine/scripts/` comes with a test there. What the suite cannot see is orchestrator prose behaviour; for that, in a scratch project run `/maister:init`,

`.maister/tasks/`.

## Non-obvious behaviors

- **Skills and agents are not interchangeable.** Skills run in the main agent via the Skill tool (they may spawn subagents). Agents run via the Task tool. On Claude Code subagents can dispatch subagents, to a depth the host limits (three levels below the main thread); on Copilot they cannot — the build grants no agent the agent tool, because Copilot runs each subagent level under a session of its own, and the freeze records every Copilot run's delegation as `inline`. Either way orchestrators, not leaf agents, run workflows: every source agent carries the containment sentence — it never starts another workflow, a command or an orchestrator skill, and loads only a skill its own instructions name — and `make validate` fails an agent without it. Details: `orchestrator-patterns.md` § 1.
- **Destructive-command guard.** `hooks/block-destructive-commands.mjs` blocks `git stash` (all but its read-only `list` and `show`), `reset --hard`, `checkout .`, `clean`, `push --force`, `rm -rf` for every subagent except those in its whitelist (`test-suite-runner`, which runs the project's own check commands as spelled), matched on the bare name or this plugin's own spelling of it, `maister:<name>` (both hosts report a plugin agent as `<plugin>:<name>`, and the plugin is `maister` on both); another plugin's agent of the same name is guarded. `task-group-implementer` is deliberately *not* whitelisted (it runs in parallel waves). Its scope is subagents only and data-loss commands only: it is not a guard on the main session, and not on outward actions (commit, push, pull requests), which the host's permissions and the person decide. Add an agent only for a blocked command its own instructions need, with the reason in the hook's comment.
- **Session-start hooks inject rules into every consumer session** (`hooks/skill-invocation-reminder.mjs`, `hooks/post-compact-reminder.mjs`): `/maister:*` commands must be invoked via the Skill tool first, and orchestrators must `AskUserQuestion` at every gate. Don't write skill/agent prose that contradicts them.
- **The gate rule.** An orchestrator asks in-session when `orchestrator.driver.kind` is absent or `terminal`; ask at every gate; **pro edition, driven sessions**: when `orchestrator.driver.kind` is `cockpit` or `dispatch`, suspend with one `gate-request` call — see the pro register § E2. Both reminder hooks, the six orchestrator Step-0 blocks — the five workflow hand-offs and the workflow engine's own — the framework patterns and this file all carry the same sentence, byte-identical; change them in lockstep. `make validate`'s gate-rule lint holds the copies at an exact count — 8 files with the full sentence, 10 with its tail (the two reminder hooks carry only the tail) — so a copy added on purpose updates the Makefile's count together with this list.
- **Hooks.** Every hook is a zero-dependency Node `.mjs`, run in exec form (`command: node` + `args` on Claude Code, `exec: node` + `args` in `platforms/copilot-cli/hooks.json`), so no hook needs bash or jq. `hooks.json` registers the two session-start reminders, the edition check and the destructive-command guard, and under `modules` one Claude Code hooks module, `display.mjs`, which only reads the engine's display files and draws them; it never denies or rewrites a call. The Copilot variant's `hooks.json` adds one hook of its own, `hand-over-question.mjs` on `ask_user`: it puts the call the engine printed (`.ask.json` beside the run's state) in place of the one the session retyped, once and only while fresh, and fails open. Gate enforcement is a Pro Edition feature and does not live in this repository.
- **Engine-only workflows; 2.x directories are refused on resume.** `development`, `research`, `performance`, `migration`, `product-design` and `mockup-studio` run only on the workflow engine — there are no prose orchestrators, no prose twins and no opt-out switch. A task directory with no `workflow:` block is refused by the engine's `resume-check` verb, which writes nothing in the run, which every resume route reaches and which holds the one operator message. For a run it accepts it records the session's display pointer, so the Claude Code mod draws a resumed run from there on.
- **No bundled browser tool.** The plugin ships no MCP server. Browser steps (the e2e verifier, the user-docs generator, the mockup gallery) name capabilities and use whatever browser tool the session has, by the order and rules in `skills/orchestrator-framework/references/browser-tools.md`, which also holds the no-browser warning; a session with none is warned, never failed. `make validate`'s browser-tool lint keeps a server, an output-folder path or plugin-scoped tool names from coming back.
- **Never auto-rollback.** On failure workflows stop, analyze, and ask the user (`agents/implementation-runner.md`).
- **Artifacts are anchored to the task directory.** Everything a workflow produces goes under `.maister/tasks/<type>/<YYYY-MM-DD-name>/`, never into project directories.
- **The Copilot build rewrites source.** `build.sh` keeps `/maister:<name>` and `maister:<agent>` as written (Copilot namespaces a plugin's commands, skills and agents under the manifest name, which is `maister` on both hosts) and turns any other `maister:<skill>` into the bare `<skill>` the skill tool takes, flattens commands, renders the marked picker passages for a picker without previews, rewrites `AskUserQuestion` → `ask_user`, a dispatch of the `Explore` agent type → Copilot's `explore`, `/plugin` install commands → `copilot plugin`, and `CLAUDE.md` → `.github/copilot-instructions.md` in skills (`.claude/CLAUDE.md` → `AGENTS.md`), ships the session-start reminder, the destructive-command guard and the question hand-over under the variant's own `hooks.json` with each script's `const HOOK_SHAPE` line switched to Copilot's top-level output shape, switches `lib/host.mjs`'s `SHIPPED_HOST` to `copilot`, which the engine reads for its host, turns an agent's `haiku` into a `model` list of lightweight Copilot models (source agents otherwise name no model — `make validate` refuses `model: inherit` — so an agent runs on the session's model unless its call carries one), rewrites `--host=claude` → `--host=copilot` so `dispatch-model` answers with Copilot model ids, and the field pair `` `model` and `effort` `` → `` `model` and `reasoning_effort` ``, Copilot's name for the per-call effort, and gives every agent a tool allowlist without the agent tool, so no Copilot subagent dispatches one: Copilot runs every subagent level under a session of its own, which a binding to the driver's session does not cover, and `make validate` fails a variant agent that grants it. Write source that stays correct after those substitutions.

## Branches & releases

- `master` — stable. Marketplace name `maister-plugins`, version `X.Y.Z`.
- `beta` — pre-release. Marketplace name `maister-plugins-beta`, version `X.Y.Z-beta.N`.
- The version is hand-edited in three manifests — `.claude-plugin/marketplace.json` (`version`), `.github/plugin/marketplace.json` (`metadata.version` and its entry's `version`) and `plugins/maister/.claude-plugin/plugin.json` — which `make validate`'s marketplace lint holds equal; the Copilot build copies it from the plugin manifest. Bump in its own commit (`Bump version to X.Y.Z`).
- Pushing a `vX.Y.Z` tag triggers CI: it checks `dist/stable` carries X.Y.Z, tags that build `dist/vX.Y.Z`, builds, validates and creates the GitHub release. A tag below the version on `master`, from a maintenance line, is released with no dist tag.
- `.gitattributes` forces LF on `*.sh`, `*.mjs`, `*.json`, `*.yml` and `*.js` — the hooks are invoked by explicit interpreter and must not acquire CRLF on a Windows checkout.

**Promoting beta → master (squash, no force push):**

1. Read the CI conclusion and commit for `beta` in their own step; promote only on green.
2. `git checkout beta && git merge master`, which brings any fix made on `master` alone into `beta` first.
3. `git checkout master && git merge --squash beta`.
4. Set name `maister-plugins` in both marketplace files and switch the Copilot entry's `ref` from `dist/beta` to `dist/stable`; commit the feature. Then set version `X.Y.Z` in the three manifests in its own commit (`Bump version to X.Y.Z`).
5. `git push origin master`; wait for green CI on `master` and for its publish to land on `dist/stable` (its `copilot/.claude-plugin/plugin.json` reads `X.Y.Z`).
6. `git tag vX.Y.Z && git push origin vX.Y.Z`. The release workflow refuses a tag `dist/stable` does not carry, and tags that build `dist/vX.Y.Z`; it refuses a tag pushed before `master` too.
7. `git checkout beta && git merge -s ours master`. This records `master` as merged without changing `beta`'s tree, so a later `merge master` replays nothing, and both branches push as fast-forwards: no reset, no force push.
8. Check the marketplace names read `maister-plugins-beta` and the Copilot `ref` reads `dist/beta`. `-s ours` keeps `beta`'s tree, so they already should; set them if not. Set version `X.Y.Z-beta.1` for the next line in the three manifests, commit, and `git push origin beta`.
