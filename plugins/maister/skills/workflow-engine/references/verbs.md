# Verbs

The workflow engine's verbs that only some steps and the runner subagents call, and the refusals
of every verb. The invocation — one command starting with the engine path, the here-string or
the patch file, the exit codes — and the twelve verbs every run calls are the engine skill's
§ *The invocation contract*. A step number or an italic section name below is the engine
skill's, unless a file is named. Each refusal is also printed by the verb that refuses.

## The verbs some steps call

| Verb | Flags | Gives |
|---|---|---|
| `diagram` | `resolve`'s flags (`--definition`, `--overlay…`, `--profile`), plus `--out` | deterministic Mermaid text; its header names the overlays (by file name) and the profile applied, and a gate box carries its question and its options as `id: effect` |
| `move-base` | `--state`; optional `--to=<ref>`, `--reason=<text>` | Moves the run's base commit after a merge, so the next review measures the run's own work and not what the merge brought in. The base: `--to` when given; else HEAD's second parent, the merged tip, when HEAD is a merge (`merged tip: HEAD is a merge`), and HEAD when it is not (`HEAD: not a merge`), whether the run's work is committed, uncommitted or both. It writes the changed paths as `write-state` does, then a blank line and `moved: <old sha> → <new sha> (<rule>)`; the replaced base is kept under `task.base_commit.previous` with its `at` and `reason`. A target that is the base already writes nothing and prints one line, `unchanged: <base sha> (<rule>)`, exit `0`. Refusals below |
| `area-brief` | `--state`, `--node` (the convergence node that is asking), and one form: `--area=<id>` with `--json` and `--picker=rich`; `--area=<id>` with `--ask`, optionally `--details`; `--area=<id>` alone; or `--patch-file=<run>/.state-patch.json` with `--area` repeated or omitted | One decision area of the brainstorm, as a picker in the field shape of `gate-brief --json`, as its full write-up in markdown, or written as a driven question set to the patch file (`references/in-node-questions.md` § *Decision areas from the brainstorm*). A file it cannot use is one `warning: decision-areas-…` line on stderr, exit `0`, and the node composes the area itself. Writes no state and no `display/next.json` |
| `finding-brief` | `--state`, `--node` (the reviewing node that is asking), `--findings-file=<file in the run>`, and optionally `--patch-file=<run>/.state-patch.json` | The node's findings that need a decision as one question set, printed as JSON or written to the patch file (`references/in-node-questions.md` § *Findings that need a decision*). A file it cannot use is one `warning: finding-list-…` line on stderr, exit `0`, and the node composes the questions itself. Writes no state |
| `subrun-path` | `--state` (the parent's), `--node` (its `workflow:` node) | JSON on stdout: `{ok, node, workflow, task_path, run_id, parent, recorded, existing}` — the child run's directory relative to the project root and its run id, `parent` the `{run, node}` link the child's freeze sends as `orchestrator.parent`, as the parent recorded them (`recorded: true`) or as the sub-run naming rule gives them, with `existing` `absent`, `empty` or `adopt` (*Sub-runs*). The only source of a child's directory: never work it out by hand. Exit `1` with `{ok: false, code, message}` for the refusals below and for `subrun-on-dir-node`, `subrun-recursion`, `subrun-target-unresolved` and `subrun-child-foreign` (`references/sub-runs.md`); a definition that drifted since the freeze is one `warning: subrun-path-graph-drift` line, exit `0` — reads the run, writes nothing |
| `import` | `--state`, `--to=<folder of the run>`, repeatable `--from=<file or directory>` inside the project, or inside the workspace root of a member run the cockpit drives (absolute, or relative to the project root), optional `--as=<name>` with a single `--from` | Each source copied into `<to>/<its name>` (`<to>/<as>` when renamed), byte for byte, a directory recursively and a link as what it points at, replacing an earlier copy; JSON on stdout: `{ok, to, copied: [{from, to, files}], skipped: [{from, code, message}]}`, every path relative to the run and spelled with `/`. **The only way a node brings context into its run: never a shell copy**, which a driven session's permissions refuse, and never the file tools, which cannot carry a binary. A source it could not copy is listed under `skipped` — `import-source-missing`, `import-source-outside` (it, or a link it holds, leads outside the project once links are resolved — or outside the project and its workspace, for a member run the cockpit drives, whose workspace is the nearest one above it whose `.maister/umbrella.yml` declares its checkout; nothing of it is copied), `import-source-overlaps` (it holds the destination or lies in it) or `import-copy-failed` — the rest are still copied, and the exit is `1`; what a skipped source means for the step is the step's to record. Exit `1` with `{ok: false, code, message}` for the refusals below — writes the copies, never state |
| `wave-start` | `--plan` (the run's `implementation/implementation-plan.md`), `--wave=<K>`, `--groups=<N>[,<M>…]` | appends `## <clock> - Wave K Started: Groups N, M` to the work log beside the plan and re-projects the run's displays through an empty state write; JSON on stdout `{ok, wave, groups, logged, reprojected}`. A repeated call appends nothing; a group the plan lacks or already marks done is refused (`wave-start-unknown-group`, `wave-start-group-done`), nothing written |
| `group-done` | `--plan`, `--groups=<N>[,<M>…]`, `--entry-file=<plan folder>/.work-log-entry.md` (the body; with several groups, one `## Group N` line opening each part) | records accepted groups in one call: marks their open step checkboxes, runs `sync-plan`, appends `## <clock> - Group N Complete (wave K)` with the body for each, the wave read from the last start naming the group, and re-projects; JSON on stdout `{ok, groups: [{group, wave, marked, logged}], sync, reprojected}`. Idempotent: an entry already logged under its wave is not appended again. A sync or re-projection that fails is a `warning:` line, exit `0`. Each refusal (`group-done-…`) says what was written and how to finish — a log that cannot be written after the plan was marked is finished by the same call run again; the entry file is deleted once its entry is in the log |
| `sync-plan` | `--plan` (the run's `implementation/implementation-plan.md`) | sets the plan companion's `data-group` / `data-step` markers to the plan's checkbox state; JSON on stdout with `written` and the groups the companion has no marker for — idempotent, and a no-op that names its reason when there is no companion or the run's `html_output` is off |
| `dispatch-model` | `--agent=<name>[,<name>…]`, `--host` (`claude` or `copilot`, the host the session runs on), optional `--state` (the run's), `--node` (with `--state`, the node that dispatches) and `--tier=light\|standard\|deep` (a task group's plan tier, read only for an agent whose entry is `choose: by-plan-tier`) | One line per agent, in the order asked: `<agent>: model <model>, effort <effort> — source: <level>`, where `omit` means the call carries no such field and the host decides. Copy the values into the agent call beside its type. Then, after a blank line, any `note:` lines: the agent's budget on the rung, saying to ask first once it is used up; the agents a `--tier` was ignored for, which resolve as without one; and one note when the project's `.maister/config.yml` changed since the freeze, the run keeping what it froze. With `--state` it reads the block the freeze recorded and scopes by the run's workflow and `--node`; without it, outside a run, it reads `.maister/config.yml`, and a finding about it is one `warning: subagents-…` line, exit `0` — reads only |
| `review-brief` | `--state` (the run's), or `--task-path` (a task directory outside a run) with `--base`; optional `--base` (the commit to measure from, for a run frozen before `task.base_commit` was recorded), `--cycle=<N>`, `--recheck=tests-only\|reviews` with `--fixed-issues=<id>[,<id>…]`, or `--refresh` | Writes `verification/review-brief-<N>.json` in the run and prints its absolute path: what one verification cycle reviews, measured once from the run's base commit — the changed files (untracked included, the project's `.maister/` never) with their status and line counts, each marked `untracked`, `generated` (a lock file, minified output, a path marked `linguist-generated`) or `data` (fixtures, data files, a large file of a data or config format — never source code for its size) where it is, the diffstat, from cycle 2 on the fix since the previous cycle's snapshot (`fix`: the two snapshots and the files between them), `documents` (the paths of the run's spec, plan, work log, clarifications, audit and the state holding its decisions, those present), the plan's group counts, the test result and the project's other checks (`checks`; a failure the base has too marked `failed_on_base` in the test result and `fails_on_base` on its check), the project profile (`profile`: its fields with `source: config` — in a run the copy the freeze recorded, standalone the `project:` key of `.maister/config.yml` — or `{source: none}`, when each reviewer infers it), the reviewers' findings contract, and on a re-check the issues with the reviewer owning each. After `move-base` the first cycle built is a full one: `fix` is `null`, `recheck` is `null` and `base_moved_from` names the previous cycle's base; a re-check asked after a move becomes a full cycle with a `warning: review-brief-base-moved: …` line naming both bases. The working tree is captured as a tree id through a temporary index: the user's index, commits and stash are never touched. Without `--cycle`, a cycle never merged is built again under its number, else the next one is taken; `--refresh` only re-reads the cycle's test result into its brief. A part it cannot fill — a snapshot that fails or outruns its budget included — is one `warning: review-brief-…` line and the brief is written without it, exit `0`. Refusals below |
| `findings-merge` | `--state`, or `--task-path`; optional `--cycle=<N>` (default: the last cycle with a brief) | Merges the cycle's `verification/<reviewer>-findings.json` files with the previous cycle's merged list into `verification/findings-<N>.json`, copied to `verification/findings.json`: duplicates across reviewers folded (one path, lines within ten, one category family; the highest severity, `severity_disagreement` when they differ), ids kept across cycles, a finding not reported again left open as `not_reported` unless a fix diff since touched it, a finding marked `outside_change` counted only when critical and otherwise moved to `out_of_scope`, a finding marked `fails_on_base` moved there at any severity when its evidence quotes the base (without evidence it is counted, with one `warning: findings-merge-base-evidence` line), a re-check's answers applied and its new findings outside the fix diff moved there too; the fix's hunks are read from git between the two snapshots its brief names (where git cannot answer, the fix is matched by its files, with one warning). JSON on stdout `{ok, file, cycle, mode, counts, failures, issues_found}` — `failures` the brief's failing tests and checks split into `introduced` and `on_base` (`{checks: [names], tests: <count>}` each; null with no test result and no checks; a check is in `on_base` only when the test suite's finding for it — its title naming the check or quoting its command, or its location a path the command names — was set aside with evidence), which the verdict reads, and `issues_found` in the state's issue shape, which a `--state` merge also records in the run's `verification_context` (a refused write is one `warning: findings-merge-state-unwritten` line, and the caller records it then). Running a cycle's merge again gives the same result. A file or finding it cannot use is one `warning: findings-merge-…` line, exit `0` |
| `project-profile` | the detected profile as one JSON object (`kind`, `runtime`, `deploy`, `exposure`, `data`, `scale`, `ui`, each optional) in `.maister/.project-profile.json`, named by `--patch-file` and deleted once written — there is no run, so the file sits beside `config.yml` — or on stdin; optional `--fill` | Writes the project profile `init` detected into `.maister/config.yml` under a top-level `project:` key — appended after one blank line, the file created when absent, every other line unchanged — only when the file has no such key; an existing one is kept as it is. A field left out, null or with a value it does not take is written commented out with the values it takes, the last also a `warning: project-profile: …` line. Prints JSON: `action` (`created`, `appended` or `kept`), `file`, `profile` (the fields written) and `block` (the text written, null when kept), exit `0`; input that is not an object is refused `project-profile-bad-input`, exit `1`, nothing written |
| `runner-result` | `--state`, `--node` (the verification node the runner ran for); the result as JSON by here-string, or `--patch-file` naming it in the patch file | The verification runner's result, checked against its shape (`implementation-verifier/SKILL.md` § *The runner's result*), stamped with the node, the node's attempt and `verification_context.cycle`, and written to `verification/runner-result.json`; the file as written on stdout, which the runner returns as its final message. The patch file is deleted once it landed and kept on a refusal |
| `runner-step` | `--state`, `--node` (the verification node that is running), optional `--answered` (the node has just recorded the answers to the runner's decision) | The node's next step as one JSON object: `inline` with the reason when the run records no nested delegation; `dispatch` with `resume` — `fresh`, `auto` (continue from the cycle files) or `{cycle, decisions_file}`; `ask` with the cycle, the decision's kind, its findings list, whether the stopping question is put, with the open critical and warning counts (`open`) when it is, and `asking` (`session`, `suspend`, or `none` when only the policy can settle it); `close` with the verdict, the report, findings and companion paths and the counts, and `undecided: true` when the attempt's last decisions file ended the loop undecided; `unavailable` with the runner's reason; `wait` with `pending` (each agent's `id`, `agent` and `output`) when the runner would continue from the files while an agent it sent in this session is still out. It writes `verification/decisions-<cycle>.json` from the answers recorded in the node's attempt, or from the defaults when nobody can be asked; the defaults give the stop `undecided` while a warning or critical is open, else `continue`. A result file it cannot use is one `warning: runner-result-unusable` line, exit `0` |
| `in-flight` | `--state`, `--node`, optional `--runner`; one of `--record=<id>:<output>[,…]`, `--agents=<id>:<agent id>[,…]` or `--ended=<id>[,…]` | The agents a runner's loop sends, in `<runner>/in-flight.json`. `--record`, before the agents are sent: each stamped with the calling session, the clock and (verification) the cycle, its stale output deleted — in verification only the same cycle's: a file an earlier cycle left is kept, its fingerprint in the record's `kept`, and counts as the output only once it changes. `--agents` attaches the ids the host gave at launch; `--ended` marks agents whose completion came without their output. JSON on stdout `{file, agents}`. An agent is still out while its record names this session, belongs to the current verification cycle (a record without a cycle always does), is not ended and its output is not written |

## Refusals

`run-context`, `prior-context` with `--node`, `node-brief` and `dispatch-model` refuse with exit `1`, an empty stdout and the code first on stderr; nothing was written:

| Refusal | Response |
|---|---|
| `run-context-state-unreadable` | `--state` cannot be read or parsed as a state document, and nothing was read further. Point `--state` at the run's `orchestrator-state.yml` — the run directory this node belongs to — and run the verb again. |
| `run-context-not-a-run` | The file carries no `workflow:` block: the engine never froze it, so it has no nodes and no run context. Run the verb on the state of a frozen run — freeze it first through `write-state` (Step 4) — and never write the block by hand. |
| `run-context-unknown-node` | `--node` is not a node of the run's frozen graph, or names `held-approval`, which delegates nothing. Name the node about to delegate, exactly as `workflow.nodes` spells it, and run the verb again; no state write fixes this. |
| `node-brief-state-unreadable` | `--state` cannot be read or parsed as a state document, and nothing was read further. Point `--state` at the run's `orchestrator-state.yml` — the run directory this node belongs to — and run the verb again. |
| `node-brief-not-a-run` | The file carries no `workflow:` block: the engine never froze it, so it has no nodes to brief. Run the verb on the state of a frozen run — freeze it first through `write-state` (Step 4) — and never write the block by hand. |
| `node-brief-unknown-node` | `--node` is not a node of the run's frozen graph, or names `held-approval`, which is briefed by `gate-brief`. Name the node about to run, exactly as `workflow.nodes` spells it, and run the verb again; no state write fixes this. |
| `dispatch-model-state-unreadable` | `--state` cannot be read or parsed as a state document, and nothing was read further. Point `--state` at the run's `orchestrator-state.yml`, or leave it off outside a run, and run the verb again. |
| `dispatch-model-not-a-run` | The file carries no `workflow:` block: the engine never froze it, so it recorded no subagents block. Run the verb on a frozen run's state, or without `--state` when no run is under way. |
| `dispatch-model-unknown-node` | `--node` is not a node of the run's frozen graph. Name the node that dispatches, exactly as `workflow.nodes` spells it, and run the verb again; no state write fixes this. |

`move-base` refuses with exit `1`, an empty stdout and the code first on stderr, each message ending "Nothing was written." and the next step; a missing `--state` is a usage error, exit `2`. The checks run in this order:

| Refusal | Response |
|---|---|
| `move-base-state-unreadable` | `--state` cannot be read or parsed as a state document. Name the run's `orchestrator-state.yml` with `--state` and run the verb again. |
| `move-base-no-repository` | The project is not inside a git repository, git is not installed, or a status or ancestry read failed partway. A run outside git has no base to move; otherwise fix what git reports and call `move-base` again. |
| `move-base-merge-in-progress` | A merge is in progress (`MERGE_HEAD` exists). Commit the merge first, then call `move-base` again. |
| `move-base-no-base` | The run records no `task.base_commit`, or the recorded commit is gone from the repository. Give `review-brief --base` for this run instead. |
| `move-base-bad-ref` | `--to` names no commit. Name a commit, a branch or a tag. |
| `move-base-not-ancestor` | The run's base is not an ancestor of the target, so the review would lose part of the run's history. Name a commit that descends from the base with `--to`. |
| `move-base-not-in-head` | The target is not an ancestor of HEAD, or HEAD names no commit. Name a commit the current branch already holds with `--to`, or commit on the current branch first. |

`review-brief` refuses with exit `1`, an empty stdout and the code first on stderr, and `findings-merge` with exit `1` and the refusal as JSON on stdout; nothing was written:

| Refusal | Response |
|---|---|
| `review-brief-state-unreadable` | `--state` cannot be read or parsed as a state document. Point it at the run's `orchestrator-state.yml` and run the verb again. |
| `review-brief-task-unreadable` | `--task-path` is not a directory. Point it at the task directory under review. |
| `review-brief-not-a-repository` | The project is not inside a git repository, or git is not installed, so there is no change to measure. Run verification from the project's checkout; without git the reviewers find their scope as they did without a brief. |
| `review-brief-no-base` | The run has no `task.base_commit` — it was frozen before the key was recorded — or a standalone call gave no `--base`. Run the verb again with `--base=<the commit the work started from>`; never guess one. |
| `review-brief-bad-base` | `--base`, or the run's recorded base, names no commit of the repository (history was rewritten since). Run the verb again with `--base` naming the commit the work started from. |
| `review-brief-no-previous` | A re-check builds on the previous cycle's brief, and there is none. Build a full brief instead (no `--recheck`), or name the right `--cycle`. |
| `review-brief-no-brief` | `--refresh` found no brief for the cycle. Build the cycle's brief first: the same call without `--refresh`. |
| `findings-merge-state-unreadable` | `--state` cannot be read or parsed as a state document. Point it at the run's `orchestrator-state.yml` and run the verb again. |
| `findings-merge-task-unreadable` | `--task-path` is not a directory. Point it at the task directory under review. |
| `findings-merge-no-cycle` | The run's `verification/` holds no review brief and no reviewer findings file, so there is no cycle to merge. Build the cycle's brief and run the reviews first. |

`runner-result`, `runner-step` and `in-flight` refuse with exit `1`, an empty stdout and the code first on stderr; nothing was written:

| Refusal | Response |
|---|---|
| `runner-result-state-unreadable`, `runner-step-state-unreadable`, `in-flight-state-unreadable` | `--state` cannot be read or parsed as a state document. Point it at the run's `orchestrator-state.yml` and run the verb again. |
| `runner-result-unknown-node`, `runner-step-unknown-node`, `in-flight-unknown-node` | `--node` names no node of the run, or names a gate. Name the verification node that runs the loop, exactly as `workflow.nodes` spells it. |
| `runner-result-not-running`, `runner-step-not-running`, `in-flight-not-running` | The node is not `running`, and only a running node hands its loop to the runner. Start it through `write-state` first, or name the node that is running. |
| `runner-result-invalid` | The result breaks the runner's result shape at the field the message names. Correct that field and send the whole result again; the patch file is still there. A `waiting` result names in `pending` only agents recorded with `in-flight --record` in this attempt; an `unavailable` result is refused while an agent this session sent is still out — send `waiting` naming those agents instead. |
| `in-flight-invalid` | The flag the message names breaks the record: not exactly one of `--record`, `--agents` or `--ended`; an id that is not a lowercase slug; an output outside the runner's folder of the run or naming one of the loop's own files; or an agent with no record in this attempt. Correct the flag and run the call again; nothing was recorded. |

`subrun-path` refuses with exit `1` and the refusal as JSON on stdout, like `resume-check`; nothing was written:

| Refusal | Response |
|---|---|
| `subrun-path-state-unreadable` | `--state` cannot be read or parsed as a state document. Point `--state` at the parent run's `orchestrator-state.yml` and run the verb again. |
| `subrun-path-not-a-run` | The file carries no `workflow:` block: the engine never froze it, so it has no `workflow:` node to start a child. Run the verb on the parent's frozen state. |
| `subrun-path-unknown-node` | `--node` is not a node of the run's frozen graph. Name the `workflow:` node that starts the child, exactly as `workflow.nodes` spells it; no state write fixes this. |
| `subrun-path-definition-unread` | The definition the parent froze cannot be re-read, so the workflow the node starts is unknown. Restore the file its `workflow.source` names, then run the verb again; never type the child's directory by hand instead. |
| `subrun-path-not-a-subrun` | The node runs a `skill:`, `agent:` or `direct:` target, not a `workflow:` one, so it starts no child run. Name the `workflow:` node. |

`import` refuses with exit `1` and the refusal as JSON on stdout; nothing was copied:

| Refusal | Response |
|---|---|
| `import-state-unreadable` | `--state` cannot be read or parsed as a state document. Point `--state` at the run's `orchestrator-state.yml` and run the verb again. |
| `import-not-a-run` | The file carries no `workflow:` block: the engine never froze it. Import into a frozen run; freeze first through `write-state` (Step 4). |
| `import-destination-outside` | `--to` is absolute, climbs with `..`, or reaches outside the run through a link. Name the folder relative to the run directory — the one the step's prose names — and run the verb again; never copy by hand instead. |
| `import-destination-reserved` | `--to` is the run directory itself, or lies under `gates/` or `display/`, which the engine writes. Name a folder of the run's own, such as the step's `analysis/…-context/`. |

**A skipped source is the step's to judge.** Supporting context, such as research, an
architecture or a context pack, becomes an `open` risk that names what was skipped and the
source path the later steps read instead. The step then goes on. Only an input the step says it
cannot work without fails it. Never ask a person to copy a file in by hand. A source skipped as
`import-source-outside` is recorded by the same rule; it is the one skip a person can clear, by
copying the file into the project, so the recorded risk or summary carries the verb's message.
